# Pipeline לעדכון שבועי — מצפן הבחירות

**נוצר:** 2026-08-07 (בעקבות סבב העדכון הראשון שכלל את בית ציוני, חוק לימוד תורה, חוק המעצרים).
**מטרה:** תהליך חוזר, ניתן להרצה עצמאית (ע"י Claude או ידנית), לעדכון האתר מדי שבוע לקראת הבחירות ב-27.10.2026.

---

## 0. עיקרון-על: תעמולה מול עובדות

לפני כל שינוי נתונים, סווג כל פריט מידע:
- **עובדה** (מזינה `actual`): תוצאת הצבעה רשמית, תאריך, פרישה/מינוי בפועל.
- **תעמולה** (מזינה `declared` בלבד, ורק אם ניתנת לניסוח כעמדה על סולם 1–7): הצהרת השקה, סיסמת קמפיין.
לעולם לא להזין רטוריקה ריקה כנתון.

## 1. שלב מחקר (מדי שבוע)

חפש (עברית + אנגלית, מקורות: ynet, מעריב, כלכליסט, הארץ, N12, ישראל היום, כאן, ynet, IDI):
1. מפלגות חדשות / פיצולים / מיזוגים שהוכרזו השבוע.
2. הצהרות/שינויי עמדה משמעותיים של ראשי המפלגות הקיימות.
3. סטטוס הבחירות (האם משהו השתנה בלו"ז 27.10 / 7.9 סגירת רשימות).
4. סקרים עדכניים — **קח ממוצע/2+ מקורות, לעולם לא סקר בודד**.

תעד ממצאים גולמיים בקובץ מחקר מתוארך חדש: `docs/YYYY-MM-DD-update-research.md` (בהשראת [docs/2026-08-update-research.md](2026-08-update-research.md)).

## 2. שלב API הכנסת — מקור האמת להצבעות ולסיעות

**חשוב:** ה-endpoint הישן (`Odata/Votes.svc/`, OData v3) מת מבחינת כנסת 25 (תקוע על כנסת 24). ה-endpoint החי הוא `OdataV4/ParliamentInfo/`. ר' [docs/knesset-api-research.md](knesset-api-research.md) לפרטים.

```bash
# 1. בדוק אם סיעות כנסת 25 השתנו מול parties.json
npm run sync-parties

# 2. לכל הצבעה מכריעה שזוהתה במחקר — משוך אותה ישירות מה-API
npm run fetch-vote -- "מילות חיפוש מכותרת החוק" --after 2026-08-01
```

`fetch-vote` מדפיס טבלת בעד/נגד לפי מפלגה (מאומתת מול תוצאה רשמית) + שלד JSON מוכן להדבקה ל-`anchor-votes.json`. **את שדה `axes` (ציר + pole) ואת ה-`weight` יש לבחור ידנית** — זו החלטה עריכתית, לא ניתנת לאוטומציה. הסתכל על הצבעות עוגן דומות קיימות לעקביות (חפש לפי axis ב-`anchor-votes.json`).

אם יש MK שלא ממופה (unmapped) — בדוק אם זו סיעה שכבר ב-IGNORE_LIST (נעם, הימין הממלכתי) או אם צריך למפות סיעה חדשה ב-`FACTION_TO_PARTY` (גם ב-`scripts/fetch-knesset-vote.mjs` וגם ב-`scripts/sync-parties.js` — שמור אותם מסונכרנים).

## 3. שלב הזרקת נתונים

1. **הוסף הצבעות עוגן** ל-`src/data/anchor-votes.json` (מהשלד שנוצר בשלב 2).
2. **מפלגות חדשות**: הוסף ל-`src/data/parties.json` לפי הפורמט המלא (declared/actual/confidence/reliability/gaps) — לדוגמה `beit_tzioni` שנוסף ב-2026-08-07. עבור מפלגה חדשה ללא היסטוריית הצבעות: `actual` ≈ `declared`, `confidence` נמוך (0.25–0.55), `reliability.promise_keeping/execution` = `null`/0.15.
3. **מנדטים**: עדכן `seats` לפי ממוצע סקרים עדכני. **אל תמציא — אם מקור חסר למפלגה מסוימת, השאר את הערך הקודם ותעד זאת.**
4. **הרץ מחדש את חישוב ה-actual**:
   ```bash
   npm run update-scores
   ```
5. עדכן תאריכים ב-`src/components/About.tsx` **וגם** `src/components/Welcome.tsx` (יש שני מקומות נפרדים עם תאריך "עודכן לאחרונה"!) וב-`src/components/Results.tsx` (שורת `methodology v1.0 · data YYYY-MM`).
6. **אל תשנה מבנית** (מיזוג/פיצול ישויות קיימות) בלי החלטה מפורשת — מצבים כמו בל"ד/רע"ם/סמוטריץ'-בן גביר/סער הם נזילים; אם לא ברור לגמרי, תעד ב-doc המחקר והשאר לביקורת אנושית.

## 5. שלב בדיקת E2E בדפדפן (5 הרצות מדומות)

הרץ `npm run dev`, פתח בדפדפן, והרץ את השאלון המלא 5 פעמים עם פרופילי תשובה שונים (קבוע-1, קבוע-7, קבוע-4/ניטרלי, רנדומלי, "נוטה" עם רעש) ווודא:
- אין קריסות / שגיאות קונסולה.
- הציונים בטווח 0–100%, ממוינים יורד.
- ריצות "קבוע-1" מול "קבוע-7" מניבות **מפלגות מובילות שונות** (סימן שהאלגוריתם באמת מגיב לתשובות).
- מפלגה חדשה שנוספה (למשל בית ציוני) מופיעה בתוצאות ולא שוברת דבר.

**הערה טכנית חשובה:** בדפדפן headless/hidden, `requestAnimationFrame` לא יורה בכלל, ו-`setTimeout` מוגבל (throttled) ל~1 שנייה. לכן:
- העדף לחיצות מרובות באותו tick (React מריץ אותן ב-batch אחד; יש לזה תופעות לוואי — ראה למטה) **או** לחיצה בודדת + poll נפרד.
- להרצת השאלון המלאה: הרץ פונקציית driver מבוססת `setTimeout` (לא rAF) בתור fire-and-forget (`window.__runRest(...)` בלי await בתוך הקריאה), ואז המתן בפולים נפרדים (`computer wait`, מקסימום 10 שניות לקריאה) עד ש-`window.__lastResult` מתמלא. ריצה שלמה (32 שאלות) לוקחת כ-40–70 שניות בפועל.
- קליק מרובה סינכרוני על אלמנט יחיד (כמו טוטוריאל) עלול לגרום להתנהגות לא צפויה בגלל React batching + closures מיושנים (stale closures) — עדיף קליק בודד + await בין קליקים, לא לולאה סינכרונית צפופה.

## 6. שלב סיכום ו-commit

1. עדכן/צור `docs/YYYY-MM-DD-update-research.md` עם כל הממצאים (כולל מה שלא הוזרק ולמה).
2. `git add` לקבצים הרלוונטיים (data files, components, docs, scripts) — **לא** לקבצי scratchpad/raw-data זמניים אלא אם רוצים לשמר אותם כתיעוד (כמו `docs/raw-2026-07-13-torah-law-vote/`).
3. `git commit` עם הודעה תמציתית שמסבירה את ה-*why* (למשל: "update: reflect Aug 2026 political developments — new Basic Law votes, Beit Tzioni party, poll refresh").
4. **אל תדחוף (push) אוטומטית** — זה משנה אתר לייב (Vercel). השאר commit מקומי ודווח למשתמש; דחיפה בפועל דורשת אישור מפורש בכל פעם, גם אם התהליך עצמו אוטומטי.
